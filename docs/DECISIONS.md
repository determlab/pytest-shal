# Decisions

Newest last. A row is added, never rewritten; a later row may replace an earlier one.

| # | Decision | Why | Issue |
|---|---|---|---|
| D1 | **One record per test, through `shal.record`.** Only a test whose `rig` or `check` resolves to this plugin's own fixture writes a record: exactly one, at teardown, with `shal.record.write`, into the setup file's directory (`sim`: the rootdir). A project's own `rig`/`check` fixture is left alone. Each `check()` is one step with one measurement; a bare `assert` or `pytest.fail` adds a `fail` step, any other exception an `error` step; a skip writes nothing. `sequence_version`/`setup_version` are the git blob id of the file's bytes as they are on disk (`git hash-object --no-filters`), computed without git; with autocrlf this can differ from the id git stores. **`calls` is omitted (`None`) in v0.1** (CTO, 2026-09-27): absence must not read as "no calls were made"; a SHAL follow-up adds the collector. *Open:* the pinned `shal.record` requires `calls` and always writes a list, so until SHAL accepts `None` the plugin passes nothing and records carry `calls: []`. | record.md §3/§6 R1: the shape lives in one place, `shal/record.py`. A test that does not use the plugin's fixtures writes nothing, so a plain session is unchanged (the fence's first invariant). | #1 |
| D2 | **`--shal-approve deny\|prompt\|allow`; `deny` is the default and the CI default.** `deny` seats `shal.DenyAll`; `prompt` seats `shal.ConsoleApprover` on the real terminal (with none, it denies); `allow` binds `shal.AutoApprove` to the rig's Hal only, through SHAL's `Hal.bind_approver`, and only with `--shal-setup sim`; it is never seated process-wide (the process keeps `deny`). A SHAL without `Hal.bind_approver` refuses `allow` with a usage error, checked by capability, not version. A mode named on the command line is seated for the whole session; with no option, `deny` is seated only while the plugin's own `rig` (session) or `check` (per test) is up, so the result does not depend on test order. All of this lives in `src/pytest_shal/approve.py`. | spec §4 and the CTO rulings of 2026-09-27: a gated op fails with the op named instead of hanging in CI; the plugin chooses among SHAL's approvers and never weakens the gate. Seating nothing in a plain session keeps it unchanged. | #1 |
| D3 | **The sim is the plugin's own in-memory topology** (`SIM_TOPOLOGY` in `plugin.py`, handed to `shal.load` as a mapping): one `shal,sim-i2c` bus with one `shal,sim-sensor`, id `ambient_temp`. Not a path into SHAL's package data. Its `setup_version` is a hash of the mapping's canonical JSON. | CTO ruling 2026-09-27: the first run must not depend on where SHAL keeps its samples. Both drivers ship with shal. | #1 |
| D4 | **The default `setup.yaml` is looked up in the rootdir**, not "the test dir" of spec §3. Order: `--shal-setup`, then `<rootdir>/setup.yaml`, then `$SHAL_SETUP`. | A session has one rig (spec §6: one rig, one process), and a pytest run can collect from many directories, so a per-directory lookup has no single answer. The rootdir is pytest's own one place per session. | #1 |
| D5 | **`allow` hands `approver=shal.AutoApprove()` to the rig's own `shal.load`** (replaces D2's `Hal.bind_approver` clause; the rest of D2 stands). Only with `--shal-setup sim`; the approver is fixed at load and holds for that Hal only, and the process-wide approver stays `deny` (never `AutoApprove`). A pyshal whose `shal.load` has no `approver` keyword (checked with `inspect.signature`, not by version) refuses `allow` with a usage error naming the need: pyshal with `shal.load(approver=)` — determlab/shal#217 / PR #219 (commit ae0113a). Tests that need it skip on an older pin; the refusal test skips on a newer one. | CTO ruling on shal #217: SHAL gives one Hal its own approver at load; `Hal.bind_approver` was dropped. | shal #217 |
